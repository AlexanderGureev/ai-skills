# Реализация спеки

Результат: спека реализована целиком; каждый критерий готовности доказан в логе; спека и лог перенесены или
оставлены по разделу «Завершение».

Правила полноты:

- Объём спеки не сокращать; части не откладывать; реализацию не заменять планом или описанием.
- Требование заблокировано (строки 2–3 «Спеки и реальности») — выполнить остальное; заблокированное записать в «Не
  сделано, риски, вопросы владельцу» с причиной.
- Несколько спек — по одной, полным циклом каждая, в порядке «Зависимостей».

Порядок: Старт → Реализация → Ревью → Итоговые проверки → Завершение.

## Старт

1. Найти спеку по номеру или пути в `spec/actual/`; нет — сообщить владельцу и остановиться. Спека из «Зависимостей»
   не в `spec/archive/` — вопрос владельцу до начала.
2. Прочитать: спеку; «Решения» спек из её «Зависимостей»; раздел «Принципы» навыка `review`
   (`${CLAUDE_SKILL_DIR}/../review/SKILL.md`); AGENTS.md; документацию затронутых модулей. Раздел AGENTS.md, нужный
   для работы, пуст или заготовка — вопрос владельцу.
3. Определить состояние по логу `spec/actual/NNN-название-log.md`; первая подходящая строка сверху:

   | Состояние | Продолжить с |
   | --- | --- |
   | владелец сказал «в архив» или отклонил | «Завершение» |
   | владелец ответил на вопрос из «Не сделано, риски, вопросы владельцу» | ответ — строкой в «Решения» спеки; заблокированное — новым этапом; затем «Ревью» и «Итоговые проверки» заново |
   | в «Готовности» есть итог общей проверки проекта | «Завершение» |
   | раздел «Ревью» есть | «Итоговые проверки» |
   | все этапы есть в «Что сделано» | «Ревью» |
   | лог есть | сверить «Что сделано» с `git status` и диффом; первый несделанный этап |
   | лога нет | создать лог по шаблону; «Реализация», первый этап |

   Сделанное не переделывать и не откатывать.
4. Сверить «Исходные данные» спеки с кодом. Расхождение, меняющее решение спеки, — по таблице «Спека и реальность».

## Правила на всё время работы

- Менять только то, что требует спека. Посторонний рефакторинг не делать; замеченный чужой долг записать в
  «Отступления и находки».
- Чужие правки — изменения рабочего дерева вне «Что сделано» — не трогать.
- Не коммитить; не менять staged без просьбы владельца.
- Спеку не править. Единственная правка — ответ владельца в этой сессии: строка в «Решения» вида
  `- <выбор> — владелец, ГГГГ-ММ-ДД; <почему>`.

## Реализация

1. Этапы — «Порядок работы» спеки. Если его нет: «Код, мешающий реализации»; затем пункты верхнего уровня
   «Требований» по порядку; последним — «Что удаляется».
2. До правки каждого этапа найти все места, куда она должна дойти (принцип 2 `review`).
3. После каждого этапа — запись в «Что сделано»: этап, файлы, символы.
4. Проверки:
   - после каждого этапа — проверки изменённых файлов из «Проверки изменений» AGENTS.md, кроме долгих;
   - долгие проверки (полный набор тестов, e2e, сборка, замер) — только в «Итоговых проверках»;
   - проверку повторять только после изменения кода;
   - упавшая проверка — найти причину и исправить; перезапуск без правки запрещён;
   - платные операции (платный API, облачные ресурсы) — в пределах из спеки или сообщения владельца; предела нет или
     он исчерпан — спросить до запуска.
5. Изменилось поведение или контракт — обновить README, docs, комментарии и «Карту проекта» AGENTS.md в том же этапе.

### Спека и реальность

| Ситуация | Действие |
| --- | --- |
| требование невыполнимо как написано; цель достижима иначе, и обход не меняет поведение для пользователя, контракт, формат или зависимости | сделать иначе; запись в «Отступления и находки» с причиной |
| нужно решение владельца: меняется поведение для пользователя, контракт, формат или зависимости | выполнить остальное; вопрос с рекомендацией в «Не сделано, риски, вопросы владельцу» |
| требование противоречит цели спеки или AGENTS.md | выполнить остальное; вопрос с рекомендацией в «Не сделано, риски, вопросы владельцу» |
| критерий готовности не выполняется | найти причину и исправить; критерий не ослаблять, проверку не подгонять |

## Лог

Шаблон:

```
# NNN. Название — лог

ГГГГ-ММ-ДД

## Что сделано
### Этап N. <название>
- `<файл>`: <символ> — <что сделано>

## Отступления и находки
- <что> — <почему> — <чем заменено | доказательство>

## Готовность
| Критерий готовности | Доказательство |
| --- | --- |
| 1. <критерий> | <команда и итог вывода | сценарий | скриншот | ждёт владельца: как проверить> |

Стенд и пробы: <одна строка>

## Ревью
- <находка> — исправлено | отклонено: <причина> | передано: <раздел лога>

## Не сделано, риски, вопросы владельцу
- <пункт>
```

Правила лога:

- В логе — решения и доказательства, а не ход работы.
- Критерий без доказательства в «Готовности» не выполнен.
- Раздел «Ревью» пишется всегда; нет находок — «находок нет». Остальные пустые разделы не писать.

## Ревью

1. Когда: после всех этапов, до «Итоговых проверок».
2. Запустить подагент — обычный, не fork, без контекста сессии. Передать: пути спеки и лога; список файлов задачи с
   пометкой новых; путь `${CLAUDE_SKILL_DIR}/../review/SKILL.md`; задание:
   - ревью по навыку `review` против спеки: полнота по каждому требованию, затем «Ревью кода»;
   - дифф — `git diff HEAD -- <файлы задачи>`, новые файлы читать целиком; сигналы —
     `node "${CLAUDE_SKILL_DIR}/../review/signals.mjs" HEAD -- <файлы задачи>`; остальные изменения в дереве —
     чужие;
   - находка — только подтверждённая; стиль не проверять; непрогнанные итоговые проверки — не находка; файлы не
     менять.
3. Разобрать ответ:

   | Находка | Действие |
   | --- | --- |
   | ошибка в решении спеки | по таблице «Спека и реальность»; в «Ревью» — «передано: <раздел лога>» |
   | опровергнута по коду (`file:line`) или противоречит спеке или AGENTS.md | в «Ревью» — «отклонено: <причина>» |
   | остальные | исправить по разделу «Исправление» навыка `review`; в «Ревью» — «исправлено» |

4. Круг один: исправленное перепроверить самому, повторный подагент не запускать.

## Итоговые проверки

1. После исправлений по ревью: проверки из «Критериев готовности», затем общая проверка проекта из «Проверки
   изменений» AGENTS.md — последней.
2. Упавшая проверка — исправить причину, повторить её и общую проверку проекта. Причина не устранена — критерий в «Не
   сделано, риски, вопросы владельцу» с выводом проверки.
3. Итог каждой проверки — в таблицу «Готовность».

## Завершение

Первая подходящая строка сверху:

| Условие | Действие |
| --- | --- |
| владелец отклонил | откатить свои изменения задачи, не трогая чужих правок; в лог — «Отклонено: <причина>»; перенести спеку и лог в архив, как в строке ниже |
| владелец принял («в архив», в любой сессии) | в «Доказательство» критериев «владелец» — «принято владельцем ГГГГ-ММ-ДД»; перенести, как в строке ниже |
| все требования выполнены, все критерии доказаны | `mv` спеки и лога в `spec/archive/`; ссылки на `spec/actual/NNN-` заменить на `spec/archive/NNN-` |
| есть невыполненное требование или недоказанный критерий без пометки «владелец» | оставить в `spec/actual/` |
| недоказаны только критерии «владелец» | оставить в `spec/actual/`; в отчёте — что и как проверить владельцу |

Отчёт владельцу по шаблону:

```
Сделано: <кратко>
Проверки: <итог одной строкой; упавшие — с выводом>
Проверить владельцу: <что и как | нет>
Не проверено, риски: <список | нет>
Вопросы: <из лога | нет>
Лог: <путь>
```
