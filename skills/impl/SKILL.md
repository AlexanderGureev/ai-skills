# Реализация спеки

Результат: спека реализована целиком, каждый критерий готовности доказан в логе, спека и лог перенесены или оставлены по разделу «Завершение».

Правила полноты:

- Объём не сокращать, части не откладывать, реализацию не заменять планом.
- Заблокированное требование записать в «Не сделано, риски, вопросы владельцу» с причиной; остальное выполнить целиком.
- Один запуск — одна спека; остальные из запроса указать в отчёте строкой `Дальше: <номера>, после коммита`.

Порядок: Старт → Реализация → Ревью → Итоговые проверки → Завершение.

## Старт

1. Найти спеку по номеру или пути в `spec/actual/` (если нет — проверить `spec/archive/`):
   - не найдено ни там, ни там или найдено несколько файлов → сообщить владельцу и остановиться;
   - есть раздел `## Открытые вопросы` → сообщить, что спека не закрыта в `/spec`, и остановиться;
   - спека в `spec/archive/` и видна в `git status` (не закоммичена) → вернуть спеку и лог в `spec/actual/`, откатить ссылки `spec/archive/NNN-` → `spec/actual/NNN-`, продолжить; закоммичена → доработка оформляется новой спекой, остановиться;
   - зависимость из «Зависимостей» не реализована → вопрос владельцу до начала (реализована = в `spec/archive/` без «Отклонено» в логе, либо в её «Готовности» недоказаны только критерии `[владелец]`).
2. Прочитать: спеку; «Решения» и «Отступления и находки» зависимостей; `../review/principles.md` (от каталога этого навыка); `AGENTS.md` и документацию корня и затронутых модулей. Пустой или заготовочный нужный раздел `AGENTS.md` → вопрос владельцу до начала.
3. Определить состояние по `spec/actual/NNN-название-log.md` (первая подходящая строка сверху; сделанное не откатывать):

   | Состояние | Продолжить с |
   | --- | --- |
   | владелец сказал «в архив» или отклонил | «Завершение» (если лога нет при отклонении — создать минимальный с причиной) |
   | владелец ответил на вопрос из «Не сделано…» или дал замечание | дописать в «Решения» спеки (формат ниже); удалить из лога «Ревью», строку `Общая проверка проекта` и отвеченный пункт; «Реализация», этап по этой строке |
   | в «Готовности» есть успешная `Общая проверка проекта` | «Завершение» |
   | раздел «Ревью» есть | разобрать находки без итога; «Итоговые проверки» |
   | все этапы есть в «Что сделано» | «Ревью» |
   | лог есть | сверить «Что сделано» с `git status` и диффом; правки в файлах первого несделанного этапа считать своими и доделать этап; остальные чужие |
   | лога нет | при незакоммиченных правках вне `spec/` спросить владельца (закоммитить или считать чужими) и ждать; затем создать лог; «Реализация», первый этап |

4. Сверить «Исходные данные» спеки с кодом; расхождение, меняющее решение, обработать по таблице «Спека и реальность».

## Правила на всё время работы

- Менять только нужное спеке; замеченный чужой долг записывать в «Отступления и находки».
- Чужие правки не трогать; не коммитить и не менять `staged` без просьбы владельца.
- Спеку не править, кроме строки ответа/замечания владельца в «Решения»: `- <выбор>; владелец, ГГГГ-ММ-ДД; <почему>` (она главнее меняемого требования).

## Реализация

1. **Этапы:** из «Порядка работы», иначе «Код, мешающий реализации» → пункты верхнего уровня «Требований» → «Что удаляется». Строки доработки владельца в «Решениях» идут этапами в конце.
2. **Выполнение:** на каждом этапе соблюдать `principles.md` (включая полную правку всех usages по принципу 2) и обновлять затронутые `README`, `docs`, комментарии и заполненную «Карту проекта» `AGENTS.md` (принцип 12; остальные разделы `AGENTS.md` менять только по требованию спеки или просьбе владельца). После этапа записать этап, файлы и символы в «Что сделано».
3. **Проверки:**
   - после этапа — быстрые проверки затронутых файлов из «Проверки изменений» `AGENTS.md`; долгие (полный набор тестов, e2e, сборка, замер) — только в «Итоговых проверках»;
   - упавшая проверка → найти и исправить причину; слепой перезапуск без правки запрещён (при явном сбое внешней среды — таймауте сети или стенда — допустим один повтор с записью в «Отступления и находки»);
   - платные операции — в пределах из спеки или сообщения владельца; иначе спросить до запуска.

### Спека и реальность

*Защищённые решения:* поведение для пользователя, внешний контракт (другой процесс, проект или мониторинг), хранимый формат данных, зависимости и строки «Решений» с автором «владелец» (внутренние типы и сигнатуры одного процесса сюда не входят).

| Ситуация | Действие |
| --- | --- |
| требование невыполнимо как написано, но цель достижима иначе без изменения защищённых решений | сделать иначе; записать причину в «Отступления и находки» |
| обход меняет защищённые решения или требование противоречит цели спеки / `AGENTS.md` | выполнить остальное; вопрос с рекомендацией в «Не сделано, риски, вопросы владельцу» |
| критерий готовности не выполняется | найти и исправить причину; критерий не ослаблять, проверку не подгонять |

## Лог

```markdown
# NNN. Название: лог

ГГГГ-ММ-ДД

## Что сделано
### Этап N. <название>
- `<файл>`: <символ>; <что сделано>

## Отступления и находки
- <что>; <почему>; <чем заменено | доказательство>

## Готовность
| Критерий / проверка | Доказательство |
| --- | --- |
| 1. <критерий> | <команда и итог | сценарий | скриншот | ждёт владельца: как проверить> |
| Общая проверка проекта | <команда и итог> |

## Ревью
- <находка>: исправлено | отклонено, <причина> | передано в вопросы

## Не сделано, риски, вопросы владельцу
- <пункт>
```

Правила лога:

- Записывать решения и доказательства, не ход работы; критерий без доказательства не выполнен.
- Раздел «Ревью» писать всегда (нет находок → «находок нет»); остальные пустые разделы опускать.
- Правки по ревью и итоговым проверкам записывать в «Что сделано» этапом «Исправления».

## Ревью

1. Выполняется после всех этапов, до «Итоговых проверок».
2. Запустить одного свежего подагента без контекста сессии (если в среде нет подагентов — провести ревью самому по `../review/SKILL.md` и отметить это в «Ревью» лога). Передать: пути спеки и лога; список файлов задачи (пометить новые и переименованные со старым путём); пути к `../review/SKILL.md`, `../review/principles.md`, `../review/signals.mjs` (от каталога этого навыка); задание:
   - провести «Ревью кода» по `review/SKILL.md` против спеки;
   - дифф: `git diff HEAD -- <файлы задачи>` (без коммитов или для новых файлов — читать файлы целиком); сигналы: `node "<путь>/signals.mjs" HEAD -- <файлы задачи>` (при наличии git и Node); остальные правки чужие;
   - только подтверждённые находки; стиль не проверять; непрогнанные итоговые проверки не находка; файлы не менять.
3. Записать находки в `## Ревью` сразу; итог дописать при разборе (первая подходящая строка сверху):

   | Находка | Действие |
   | --- | --- |
   | ошибка в решении спеки | вопрос с рекомендацией в «Не сделано…»; в «Ревью»: «передано в вопросы» |
   | опровергнута по коду (`file:line`) или противоречит спеке / `AGENTS.md` | в «Ревью»: «отклонено, <причина>» |
   | остальные | исправить по разделу «Исправление» `../review/SKILL.md`; в «Ревью»: «исправлено» |

4. Один подагент на проход; исправленное перепроверить самому.

## Итоговые проверки

1. Выполнить проверки из «Критериев готовности», затем последней — общую проверку проекта из «Проверки изменений» `AGENTS.md`.
2. Упавшую проверку исправить и повторить вместе с общей; неустранённую записать с выводом в «Не сделано, риски, вопросы владельцу».
3. Записать итоги в «Готовность», включая строку `Общая проверка проекта`.

## Завершение

Выбрать первую подходящую строку сверху:

| Условие | Действие |
| --- | --- |
| владелец отклонил | откатить свои правки (не трогая чужие); в лог «Отклонено: <причина>»; в архив по третьей строке |
| владелец принял («в архив», в любой сессии) | в критериях `[владелец]`: «принято владельцем ГГГГ-ММ-ДД»; в архив по третьей строке |
| все требования выполнены, все критерии доказаны | `mv` спеки и лога в `spec/archive/`; заменить `spec/actual/NNN-` → `spec/archive/NNN-` в коде, `README`, `docs` и `spec/actual/` (`spec/archive/` не трогать); при правке файлов с проверкой ссылок/линта перепроверить их |
| есть невыполненное требование или недоказанный критерий без `[владелец]` | оставить в `spec/actual/` |
| недоказаны только критерии `[владелец]` | оставить в `spec/actual/`; в отчёте указать, что и как проверить владельцу |

Отчёт владельцу:

```
Сделано: <кратко>
Проверки: <итог одной строкой; упавшие с выводом>
Проверить владельцу: <что и как | нет>
Не проверено, риски: <список | нет>
Отступления: <из лога | нет>
Вопросы: <из лога | нет>
Лог: <путь>
```
