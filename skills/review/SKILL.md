# Ревью

Цель — найти: (1) ошибки корректности; (2) изменения, после которых следующая задача того же рода требует больше
изменений. Стиль и форматирование не проверяются.

Объект — из аргумента: номер спеки или путь в `spec/` — «Ревью спеки»; диапазон git, файл или каталог — «Ревью
кода»; без аргумента — staged, а если он пуст — всё незакоммиченное (`HEAD`). Для файла или каталога задача — весь код
по пути.

Правила — принципы ниже и разделы AGENTS.md корня и затронутых модулей, которые касаются объекта. Правило AGENTS.md
главнее правила навыка.

## Принципы

**Главный принцип: сложность растёт только ради текущей задачи.**

- Сложность — понятия и связи, которые нужно удержать, чтобы безопасно изменить код: модули, абстракции, типы,
  опции, флаги, параметры, зависимости, пути выполнения, связи через границу модулей, места, где записано одно
  правило.
- Каждый добавленный элемент из этого списка оправдан текущей задачей. Удалённый элемент — выигрыш.
- Критерий: после задачи следующая задача того же рода требует не больше изменений, чем до неё.

1. **Порядок выбора решения.** Взять первый вариант, который полностью решает задачу:
   1. не делать: требование не нужно или его закрывает продуктовое ограничение (решает владелец);
   2. уже есть в проекте: использовать так же, как соседний код;
   3. платформа или стандартная библиотека;
   4. установленная зависимость;
   5. новый код минимального объёма у модуля-владельца.

   Новая зависимость — только если заменяет больше кода, чем добавляет, и её принял владелец. При равном объёме —
   вариант, корректный на граничных входах; затем — читаемый без расшифровки.
2. **Полная правка.** До правки найти все места, куда она должна дойти: вызовы, тесты, фикстуры, конфигурация,
   экспорты, документация. Решение минимально; правка доведена во всех найденных местах.
3. **Модуль-владелец.** У каждого состояния, данных, ресурса, правила и lifecycle — один модуль-владелец
   (единственный модуль, который его создаёт и меняет) и один источник истины.
   - Модуль для нового кода выбирается по источнику данных, частоте обновления и сроку жизни, а не по сходству
     результата.
   - Правило домена (предикат, формула, предел, общая константа) — одна функция или константа у модуля-владельца.
     То же выражение в другом модуле — дубль, даже в одну строку.
4. **Явные границы.**
   - Модули связаны узким API; зависимости и порядок вызовов видны в точке сборки.
   - Запрещено: собственное глобальное изменяемое состояние, скрытая регистрация, доступ к внутренностям чужого
     модуля, циклические импорты.
   - Событие — только для независимых подписчиков; иначе прямой вызов.
   - Механизм фреймворка, принятый в проекте (DI, декораторы маршрутов, store), — не нарушение; собственный скрытый
     механизм поверх него — нарушение.
   - Границу, которую можно закрепить типом, входом модуля или линтом, закреплять.
5. **Устройство соседей.** Новое повторяет слои, интерфейсы и конвенции соседа того же рода. Своя конвенция — только
   с записанной причиной.
6. **Только существующее.**
   - У каждой абстракции, опции, поля, параметра, экспорта и ветки есть потребитель — код, который сегодня их
     читает или вызывает.
   - Абстракция вводится, только если убирает существующее дублирование.
   - Значение передаётся в той форме, которую уже даёт платформа или модуль-владелец, без обёрток и преобразований.
   - Исключения: (а) значение, которое будут подбирать, — именованная константа у модуля-владельца; (б) ближайшая
     сущность того же рода, подтверждённая владельцем, — границы и типы под неё сейчас, без опций и флагов.
7. **Вторая сущность.** Вторая сущность того же рода (страница, провайдер, тип объекта, домен API) добавляется
   данными или правкой у одного модуля-владельца.
   Нарушение — копии блоков или ветки по типу в нескольких местах.
8. **Причина, а не симптом.**
   - Ошибка исправляется один раз в общем коде у модуля-владельца, после поиска всех вызовов.
   - Запрещено маскировать ошибку: таймер, повтор, порог, подобранная константа, пустой обработчик, молчаливый
     fallback, значение по умолчанию вместо обязательного.
   - Причину нельзя устранить в задаче — вопрос владельцу с рекомендацией: продуктовое ограничение, закрывающее
     класс ошибок.
9. **Явный контракт.**
   - Взаимоисключающие состояния — тип без невозможных сочетаний.
   - Внешние данные проверяются типом или схемой один раз на входе; внутренний код опирается на инварианты и не
     перепроверяет их.
10. **Замена целиком.**
    - Старая модель удаляется в той же задаче: ветки, типы, адаптеры, тесты, настройки, тексты.
    - Совместимость и миграции — только если их требует раздел «Статус» AGENTS.md.
    - Перенос и слияние кода сохраняют проверки, обработку ошибок, приоритет отказов и порядок побочных эффектов.
11. **Сложность за цифру.** Код ради производительности — только с выигрышем, подтверждённым замером; цифра записана
    в лог.
12. **Правдивые тексты.**
    - README и docs описывают текущее состояние, без истории. Меняются, только если без правки они неверны или не
      упоминают добавленные задачей поведение, команду, контракт или модуль.
    - Комментарий — только о неочевидном: причина решения, обход ошибки среды, требование порядка, единицы. Без
      номеров спек и истории правок.

**Не упрощается:** проверка на границе доверия; обработка ошибок, защищающая данные от потери; безопасность и доступ;
доступность интерфейса; то, что владелец явно потребовал.

## Ревью кода

1. **Контекст.** Спека и лог задачи (`spec/actual/`, `spec/archive/`) — переданные вызывающим, иначе по номеру из
   запроса или сообщений коммитов: цель, решения, отступления. Спеки нет — цель из запроса или сообщений коммитов, шаг
   3 — по пунктам цели.
2. **Сигналы.** Выполнить `node "${CLAUDE_SKILL_DIR}/signals.mjs" [диапазон] [-- пути]` для того же объекта; скрипт
   лежит рядом с этим файлом. Каждый сигнал — вопрос, на который нужно ответить по коду. Объект — файл или каталог, или
   нет Node — шаг пропустить.
3. **Полнота.** Для каждого требования и критерия готовности спеки: где реализовано (`file:line`) и чем проверено.
   Отступление от спеки без записи в логе — находка.
4. **Новое.** Для каждого нового модуля, экспорта, поля, опции и параметра: модуль-владелец, потребитель, источник
   данных. Нет потребителя или два источника — находка.
5. **Проход.** Читать по слоям: домен → форматы данных и контракты → внешние слои (UI, API, сервер) → инструменты и
   тесты → документация. Тесты — по требованиям спеки; данные и сгенерированное — по сигналам. В каждом слое
   проверять: «Тихие ошибки», затем принципы 1–12, затем «Классы ошибок».
6. **Вторая сущность.** Задача добавила сущность (страницу, провайдер, тип, обработчик) — перечислить файлы, которые
   изменятся при добавлении ещё одной того же рода; больше одного места — находка по принципу 7. Не добавила — шаг
   пропустить.
7. **Подтверждение.** Без подтверждения находки нет.
   - Ошибка поведения — сценарий по коду (цепочка `file:line`) или проба.
   - Структурная — `file:line` и поиск по usages.
   - Проба — короткий скрипт или тест во временной папке; сборка не позволяет — временный тест в дереве, удалить
     после проверки. Полные наборы тестов не запускать.
   - Диапазон коммитов — спеку брать на конце диапазона; находку сверить с текущим кодом. Исправленное позже — не
     находка.
8. **Ошибка в спеке.** Ошибку, заложенную в решении спеки, записать находкой с поправкой спеки, а не с обходом в
   коде. Конфликт цели и спеки — находка в «Существенно» с вариантами и ценой для владельца.
9. **Отчёт** — по разделу «Отчёт». Код не менять до просьбы владельца.

### Тихие ошибки

Проверять в каждом слое.

1. Состояние вне источника истины: кэш, флаг, счётчик или производное значение переживает событие, сохранение,
   перезагрузку или перезапуск; производное пересчитывается позже события.
2. Lifecycle: ресурс, подписка, таймер или запрос без модуля-владельца и без отмены; освобождение раньше последнего
   потребителя; повторная инициализация и её сбой. Объекту на весь срок жизни приложения очистка не нужна.
3. Граничные входы: пусто, ноль, отрицательное, переполнение, повтор, параллельный вызов, действие во время другого,
   неизвестный исход внешнего вызова (таймаут или обрыв после выполнения).
4. Вход и выход расходятся: код производит значение, которое отклоняет его же проверка; проверка стоит после
   побочного эффекта.
5. Контракт, защищённый разделом «Статус» AGENTS.md (API, схема, формат данных), изменён без миграции.
6. Ошибки и доступ: проглоченная ошибка; секрет в логе или ответе; проверка прав не в модуле-владельце.

### Классы ошибок

Находка — только то, что внесла задача.

1. **Новое прицеплено к похожему модулю.** Признаки: оговорка «кроме…» в описании модуля; поля и входы, нужные только
   новой части; один метод смешивает разные частоты обновления; правило домена в слое представления. Исправление:
   разделить по источнику данных, частоте и сроку жизни; общий только вид — общая функция в нейтральном модуле.
2. **Чужой домен ради переиспользования.** Признаки: одна сущность наследует другую; данные одной сущности в
   контейнере другой; проверки типа и пустые значения компенсируют несовпадение. Исправление: общее — в нейтральный
   модуль, сущности — равноправные потребители.
3. **Одно правило в нескольких местах.** Признаки: одинаковые проверка принадлежности, признак вида, формула или
   предел в двух модулях (у производителя и у проверяющего); одинаковые копии данных, конфигов, фикстур.
   Исправление: одна функция, константа или файл у модуля-владельца; производное считается один раз и передаётся.
4. **Второй путь к тому же.** Признаки: повторный вход в начало действия; запись одного состояния из двух мест; сборка
   данных в обход модуля-владельца формата; повторная дорогая работа (разбор, хеш, нормализация). Исправление: один
   путь через модуль-владелец.
5. **Код без потребителя.** Признаки: ветка или опция под отсутствующий сценарий; необязательный параметр, который
   передают все; экспорт или поле, которые никто не читает. Исправление: удалить. Правки по ревью проверять на этот
   же класс.
6. **Контракт не выражен.** Признаки: связь по позиции в массиве; два необязательных поля вместо union; особое
   значение (`-1`, `""`, `null`) как сигнал; проверка типа внутри функции; данные через скрытый модульный кэш.
   Исправление: тип или схема, которые выражают контракт.
7. **Попутная смена чужого поведения.** Признак: изменённая общая функция меняет результат для других потребителей.
   Исправление: пройти все usages; изменение, которого не требует задача, — изолировать; требуемое — записать в лог
   как решение.
8. **Костыль вместо модели.** Признак: таймер, повтор, порог или подобранный коэффициент снимают симптом.
   Исправление: по принципу 8.
9. **Отладка в продукте.** Признак: отладочные сценарии, флаги или инструменты в ядре или продуктовом модуле.
   Исправление: отдельный модуль, который отключается целиком.
10. **Хвосты старой модели.** Признак: поиск по старым именам находит код, тесты, настройки, комментарии или docs.
    Исправление: удалить.
11. **Отставшие тексты и тесты.** Признаки: README, docs или комментарий описывают старое поведение или другого
    модуля-владельца; утверждение теста истинно всегда; перенесённый тест проверяет меньше прежнего. Исправление:
    привести к коду.

## Ревью спеки

Пройти чек-лист. Невыполненный пункт — находка: место в спеке, сценарий, исправление.

- [ ] Цель достижима требованиями спеки.
- [ ] Подход выбран по принципу 1; упрощение требованием (продуктовое ограничение, меньше вариантов и сочетаний)
      рассмотрено.
- [ ] У каждого нового правила, модуля и данных — модуль-владелец по данным, а не по сходству (классы ошибок 1, 2).
- [ ] Вторая сущность того же рода добавляется в одном месте; нет опций и веток под отсутствующие сценарии.
- [ ] Спека не вносит техдолга; код, мешающий реализации, перечислен в «Код, мешающий реализации».
- [ ] «Что удаляется» перечисляет всё, что заменяет спека.
- [ ] Разделы спеки не противоречат друг другу и AGENTS.md.
- [ ] Каждое требование закрыто критерием готовности со способом проверки; способ выбран по риску из «Проверки
      изменений» AGENTS.md; каждая долгая проверка (полный набор тестов, e2e, сборка, замер) указана в одном критерии.
- [ ] Нет жёсткого порога для шумной метрики (время, кадры, память), который вынудит костыль.
- [ ] Пути и символы из «Исходных данных» и «Кода, мешающего реализации» существуют в коде.

## Предложения

Правила для исправлений, которые предлагает отчёт:

- Сравнить, что исправление удаляет и что добавляет. Исправление, которое не устраняет ошибку, не добавляет больше
  строк и понятий, чем удаляет.
- Не предлагать: общий класс, интерфейс или стратегию, когда общая только форма; хелпер ради 2–3 строк; флаг в общем
  пути вместо безопасного поведения по умолчанию.
- Одно правило для всех сущностей рода предпочтительнее веток по типу.
- Код, который был до задачи, — в «Не трогаю», кроме кода, мешающего реализации задачи.

## Отчёт

Шаблон. «Критично» — ошибки корректности, «Существенно» — рост сложности и нарушения принципов. Нумерация находок
сквозная; пустой раздел — «нет». В находке по спеке вместо `file:line` — раздел и пункт спеки.

```
Вердикт: <полнота по задаче; есть ли критичное; растёт ли сложность — 1–2 фразы>

Критично
1. <file:line> — <сценарий и последствие> — <подтверждение> — <исправление>

Существенно
2. <класс ошибки или принцип> — <file:line> — <почему следующая задача станет дороже> — <исправление; что удалится>

Проверено: <слой — что проверено>; …
Не трогаю: <что — причина: решение спеки без ошибки | цена не подтверждена | было до задачи>
```

## Исправление

Выполнять для находок, которые назвал владелец, или для находок ревью в навыке `impl`.

1. Ошибка поведения: сценарий или проба, которая падает без правки → правка → проба проходит. Структурная: правка →
   поиск по старым usages.
2. Обновить README, docs, комментарии и «Карту проекта» AGENTS.md со старой формулировкой. Изменилось решение спеки — запись в лог с причиной;
   спеку не править.
3. Проверки — по разделу «Проверка изменений» AGENTS.md.
4. Чужие изменения в рабочем дереве не трогать; staged не менять.
5. Повторить `signals.mjs` с тем же диапазоном; пройти свой дифф по «Классам ошибок», в первую очередь класс 5.
