# Шаблон и правила спеки

## Файл

- **Путь:** `spec/actual/NNN-название.md`.
- **Номер `NNN`:** три цифры — наибольший номер среди файлов `spec/actual/` и `spec/archive/` плюс один, взятый непосредственно перед созданием. Серия получает номера подряд в порядке выполнения.
- **Название:** латиница через дефис по сути задачи. В монорепе первое слово — приложение или пакет главного изменения (`025-web-api-keys.md`).
- **Объём:** независимые задачи — разные спеки. Деление одной задачи на серию (со связью в «Зависимостях») — только по результатам, каждый из которых проверяется отдельно и оставляет проект рабочим; деление предлагается вопросом владельцу.

## Шаблон

Разделы по порядку; раздел без содержания не писать:

```markdown
# NNN. Название

## Цель
<словами владельца: что не так сейчас; почему важно; что станет правдой и как это увидеть. Без способа решения>

## Зависимости
- NNN: <что из неё нужно>

## Исходные данные (ГГГГ-ММ-ДД)
- <факт, замер или ограничение кода>: `файл` (`символ`)

## Решения (ГГГГ-ММ-ДД)
- <выбор>; <владелец | агент, один автор>; <почему отвергнута альтернатива, если была>

## Требования
1. <проверяемое требование>
   1.1. <уточнение>
<поведение по сочетанию признаков: таблица «сочетание → результат»>

## Что удаляется
- <убираемый код, ветки, тесты, настройки, тексты старой модели>

## Границы и запреты
- <что не входит в эту задачу; её запреты сверх AGENTS.md>

## Порядок работы
<только если отличается от порядка «Требований»; номерами требований без пересказа, ревью и итоговых проверок>

## Критерии готовности
1. <проверяемый результат>; <команда | сценарий | скриншот>; требования <номера> [владелец]

## Открытые вопросы
<писать, только если на этапе 3 остались блокирующие вопросы; удалить после ответов>
```

## Правила текста

- Спека фиксирует результат и границы; способ реализации — только если без него требование неоднозначно.
- Одна проверка может закрывать несколько требований; указывать только требования, которые она реально проверяет. Общую проверку проекта из `AGENTS.md` отдельным критерием не дублировать — её запускает `/impl` последней, и она сама закрывает требования на сборку, типы и линт.
- Пометка `[владелец]` — только для приёмки владельцем (внешний вид, ощущение, работа на устройстве); не смешивать в одном критерии с тем, что агент проверяет сам.
- Текст, не задающий действие, ограничение или проверку, и ссылки на контекст обсуждения (скриншоты, файлы из чата) удалить.
- После записи проверить спеку самому по `../review/spec-checklist.md`; пробелы исправить до этапа 3.
