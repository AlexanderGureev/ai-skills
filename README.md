# ai-skills

Три навыка на цикл разработки в любом проекте — обсуждение → спека → реализация → ревью → архив — и `setup` для
нового проекта. Навыки держат порядок работы и общие принципы кода; специфику проекта разработчик пишет в AGENTS.md.

| Навык | Когда |
| --- | --- |
| `/spec <задача>` | новая задача: обсуждение без кода, вопросы раундами (ответ «В1 да, В2 нет»), спека, проверка готовности свежим подагентом. `/spec NNN` — только проверка готовой спеки |
| `/impl NNN` | реализация спеки целиком в свежей сессии: лог с доказательствами, ревью подагентом, итоговые проверки, архив. Повторный `/impl NNN` продолжает по логу |
| `/review [что]` | ревью спеки, диапазона git или модуля; без аргумента — staged или всё незакоммиченное. Находки с номерами: «исправь 1–3» |
| `/setup` | один раз в новом проекте: заготовка AGENTS.md, CLAUDE.md с `@AGENTS.md`, `spec/actual/`, `spec/archive/` |

Критерии, которые принимает только владелец (вид, ощущение, устройство), спека помечает «владелец»: такая спека ждёт
в `spec/actual/` его «в архив».

## Установка

```bash
npx skills add AlexanderGureev/ai-skills -a claude-code   # из GitHub
npx skills add ./path/to/ai-skills -a claude-code # из локальной папки
```

Затем в новом проекте — `/setup` и заполнить разделы AGENTS.md. Навыки ставятся рядом: `spec` и `impl` находят
`review` по соседнему каталогу. `signals.mjs` нужен Node; без него ревью задаёт те же вопросы по диффу.

## Спеки

- `spec/actual/NNN-название.md` и лог `NNN-название-log.md` рядом; выполненные и отклонённые — `spec/archive/`.
- Номер общий на репозиторий: наибольший в `actual` и `archive` плюс один, серия — в порядке выполнения. В монорепе
  первое слово названия — приложение или пакет главного изменения: `025-web-api-keys.md`. Задача на несколько
  приложений — одна спека.

## AGENTS.md проекта

Заготовка `setup` — разделы «Карта проекта», «Статус», «Архитектура и границы», «Правила кода», «Команды», «Проверка
изменений», «Спеки». По имени навыки ссылаются на «Статус» (совместимость и миграции) и «Проверку изменений» (какой
проверкой закрывать какой риск); остальные разделы читают как правила проекта. Названы иначе — навыки находят их по
смыслу. Правило проекта главнее общего принципа навыка `review`.

## Состав

- `skills/spec/SKILL.md`, `skills/impl/SKILL.md` — порядок работы.
- `skills/review/SKILL.md` — общие принципы кода и критерии ревью; `signals.mjs` — сигналы роста сложности в диффе
  (Node, без зависимостей).
- `skills/setup/` — `setup.sh` и шаблон `AGENTS.template.md`.
